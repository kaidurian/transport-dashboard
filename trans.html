🚂 Generate Trailer

Set Number of trains and Number of Hydraulic Groups at the top of the train list to size the dashboard: e.g. Number of trains = 2 gives you 2 trains, Number of Hydraulic Groups = 3 gives EVERY train 3 axle groups (max 4, since there are only 4 fixed groups). Both are kept in sync with Excel sheet "Input", cells B1 (Number of trains) and B2 (Number of Hydraulic Groups): editing either here writes it straight to Excel, and the ⇩ button pulls the latest value back in and resizes the dashboard to match. Define one or more trailer trains. Axle #1 of each train sits at the entered X offset — the distance from the barge's origin (0,0) to the top-left corner of the trailer; every following axle = previous axle's X − line spacing, all sharing the same Y offset — the distance from origin (0,0) to the top-left corner of the trailer along Y. X offset and Y offset are kept in sync with Excel sheet "Input", cells B5 (X offset) and B6 (Y offset): editing either field here writes it straight to Excel, and the ⇩ button next to each label pulls the latest value back in. New trains start with the same line spacing and X/Y offset as the trailer above them. Split each train's axle-line range into axle groups (e.g. axle lines 1–5 @ 25 t, axle lines 6–10 @ 50 t) and pick one of the 4 fixed groups for each range from the dropdown — or mark a group No line load for axles that carry no cargo weight. For a Goldhofer or SPMT preset trailer, each axle line is really a pair of physical axles (a right axle and a left axle sitting opposite each other) — use each group's Axle row field to apply that group to both axles, the right axle only, or the left axle only, so e.g. a 6-line/12-axle Goldhofer can have columns 1–2 in one group (both rows) while columns 3–6's right axles sit in a second group and their left axles sit in a third. If a train is actually made up of several separate physical SPMT units (e.g. a 10-line train built from a 4-line unit followed by a 6-line unit), use that train's AutoCAD split field to enter the axle-line count per unit, front → back (e.g. 4,6) — each unit then gets its own AutoCAD block insert on export, instead of one block for the whole train; leave it blank for the old one-block-per-train behavior. Rows are written to Load_Editor!B (name, e.g. Group_1_line_1) and D:G starting at row 124 (D = Line load t, E = X, F = Y, G = VCG). "📤 Push to Excel" writes each axle LINE's X/Y position and group number (no load/VCG) to sheet Adjust_Wheels, with axle lines as rows (A4 = Line 1 … A123 = Line 120) and one 6‑column block per train (Train 1 = B:G, Train 2 = H:M, Train 3 = N:S, …: left x-pos/y-pos/Group then right x-pos/y-pos/Group), and in the same click also writes each train's AutoCAD split segments to Input!A11:C30 (row 10 = "Set Train Group"): one row per split segment (or one row for the whole train if AutoCAD split is blank), column A/D/G/… = split type (e.g. GHF 4), and the next two columns = that segment's first axle line's Group Nr for the left and right axle respectively — 3 columns per train, Train 1 = A:C, Train 2 = D:F, and so on through Train 10. The same click also writes each linked train's X offset/Y offset to Input (Train 1 = B5/B6, Train 2 = E5/E6, Train 3 = H5/H6, … through Train 10) — this is the only time those cells are pushed to (they're only ever pulled automatically on panel open/refresh, never on every edit). Adjust_Wheels stores axle-CENTER positions (distance from origin 0,0 to the center of each axle), which is different from X offset/Y offset (distance from 0,0 to the trailer deck's top-left corner) — the preview's dimension callouts show both. "⇩ Refresh from Adjust_Wheels" reads the axle grid back the other way; every linked train's (Train 1-10) X offset/Y offset is then re-linked to its own Input cell pair (Train 1 = B5/B6, Train 2 = E5/E6, Train 3 = H5/H6, … 3 columns apart) rather than left as a raw axle position, so it stays the deck-corner value everywhere. Editing X offset/Y offset on the dashboard is always picked up automatically the next time you push, since nothing is cached. This same read also runs automatically the first time the panel opens (and on every refresh) whenever Adjust_Wheels isn't blank. While reading, each train's Trailer type is auto-detected from the spacing between its axle lines: exactly 1500 mm → Goldhofer, exactly 1400 mm → SPMT (anything else stays Custom / Manual), and its axle-line count is taken directly from how many Line N rows that train's block has in Adjust_Wheels.

📦 Generate Cargo

Up to 5 cargo items, linked to Excel sheet "Input", cells AZ35:BD39 (Name / W [mTe] / X [m] / Y [m] / Z [m]) and BE35:BJ39 (Length [m] / Width [m] / Height [m] / CoG to Left [m] / CoG to Rear [m] / CoG to Bottom [m]) — all in meters, unlike the mm trailer fields above. X and Y are the cargo's Center of Gravity (CoG) distance from world origin (0,0) — the same origin the trailer's X offset/Y offset use, just in meters instead of mm — and Z is the CoG height above the trailer deck. Length, Width, and Height size the box drawn in the preview, and CoG to Left/CoG to Rear/CoG to Bottom position that box — each is the distance from this item's own CoG to the box's left/rear/bottom edge. Editing a CoG field (CoGx/CoGy/CoGz) moves only the CoG sign, and editing a CoG-to-edge field moves only the box — unless the item's 🧲 Group toggle is on, in which case editing CoGx/CoGy/CoGz drags the box along with it (the offsets stay fixed) and every other field on that item is disabled, leaving only CoGx/CoGy/CoGz editable. All of these are pulled/pushed as written in Excel. Pulled automatically when this panel opens or refreshes; press "📤 Push Cargo to Excel" to write changes back (row 40's TOTAL stays a live Excel formula and is never overwritten). Below the cargo list, the 🧲 Group All section lets you nudge every cargo item — CoG sign AND drawn box together — at once: tick its toggle, then edit its own CoGx/CoGy/CoGz fields — each edit applies that same X/Y/Z delta to EVERY cargo item's CoG and box alike (regardless of that item's own individual 🧲 Group toggle), so the whole cargo set — position and shape both — slides together while every item keeps its size and its offsets from its own CoG unchanged. It resets to 0/0/0 each time it's switched on and is local-only (not written to Excel).
